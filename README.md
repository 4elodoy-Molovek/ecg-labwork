# Лабораторная работа: классификация ЭКГ

Обучение нейросетевого классификатора диагнозов по двенадцатиканальным ЭКГ из датасета PTB-XL. Работа выполняется в двух Jupyter-ноутбуках из двух проектов:

| Часть | Проект | Ноутбук | Что нужно сделать |
|:-:|---|---|---|
| 1 | [ecg-warehouse](https://gitverse.ru/unn-aicenter/ecg-warehouse) — хранилище ЭКГ | `notebooks/lab_dataset.ipynb` | загрузить PTB-XL в хранилище, собрать датасет своего варианта и экспортировать его для обучения |
| 2 | [ecg-ml](https://gitverse.ru/unn-aicenter/ecg-ml) — обучение классификаторов | `notebooks/lab_training.ipynb` | обучить классификатор на экспортированном датасете, оценить его на тестовой выборке и попробовать улучшить |

**Результат работы** — два запроса на слияние (merge request, MR), по одному в вашем форке каждого проекта. В каждом MR — ноутбук вашего варианта, выполненный и сохранённый вместе с результатами ячеек.

## Варианты

| Вариант | Коды SCP-ECG (порядок классов) | Состояния |
|:-:|---|---|
| 1 | `NORM`, `AFIB` | норма, фибрилляция предсердий |
| 2 | `NORM`, `CLBBB`, `CRBBB` | норма, полная блокада левой и правой ножки пучка Гиса |
| 3 | `NORM`, `IMI`, `ASMI` | норма, нижний и переднеперегородочный инфаркт миокарда |
| 4 | `NORM`, `LVH`, `LAFB` | норма, гипертрофия левого желудочка, блокада передней ветви левой ножки |
| 5 | `NORM`, `1AVB`, `IRBBB` | норма, АВ-блокада I степени, неполная блокада правой ножки |
| 6 | `SR`, `AFIB`, `STACH`, `SBRAD` | синусовый ритм, фибрилляция предсердий, синусовая тахикардия и брадикардия |
| 7 | `NORM`, `PVC`, `AFIB` | норма, желудочковая экстрасистолия, фибрилляция предсердий |

В варианте 6 все классы — заключения о ритме, поэтому норму в нём представляет код `SR` (синусовый ритм), а не диагностическое заключение `NORM`.

## Что понадобится

- аккаунт на [GitVerse](https://gitverse.ru);
- [git](https://git-scm.com/downloads) и [uv](https://docs.astral.sh/uv/getting-started/installation/): uv сам скачает подходящий Python (3.12 или 3.13) и установит зависимости проектов;
- среда для Jupyter-ноутбуков: Google Colab, Kaggle Notebooks или локальный запуск (VS Code с расширением Jupyter или JupyterLab);
- около 20 ГБ свободного места на диске: архив PTB-XL, распакованные записи, хранилище ЭКГ, экспортированный датасет и окружения обоих проектов.

## Порядок выполнения

### 1. Форки и ветки

Сделайте форки обоих проектов в своём аккаунте GitVerse:

- <https://gitverse.ru/unn-aicenter/ecg-warehouse>
- <https://gitverse.ru/unn-aicenter/ecg-ml>

Склонируйте **свои форки** в один каталог, рядом друг с другом: первая часть экспортирует датасет в соседний каталог `ecg-ml`. Вместо `<логин>` подставьте свой логин на GitVerse:

```bash
git clone https://gitverse.ru/<логин>/ecg-warehouse.git
git clone https://gitverse.ru/<логин>/ecg-ml.git
```

Должно получиться так:

```text
<каталог для лабораторной>/
├── ecg-warehouse/
└── ecg-ml/
```

В каждом репозитории создайте ветку для работы, например `lab-variant-<N>`, где `<N>` — номер вашего варианта:

```bash
cd ecg-warehouse
git switch -c lab-variant-<N>
cd ../ecg-ml
git switch -c lab-variant-<N>
```

### 2. Окружения

В корне каждого из двух репозиториев выполните:

```bash
uv sync
```

Команда создаст в репозитории окружение `.venv` с зависимостями проекта и ядром Jupyter. Каждый ноутбук выполняется в окружении своего проекта: `lab_dataset.ipynb` — в `ecg-warehouse/.venv`, `lab_training.ipynb` — в `ecg-ml/.venv`.

Без uv окружение можно создать через `python -m venv .venv` и установить зависимости в активированное окружение командой `pip install -e . ipykernel ipywidgets`.

Чтобы открыть ноутбук:

- в VS Code откройте каталог проекта, затем ноутбук, и выберите ядро из `.venv` этого проекта (Select Kernel → Python Environments);
- JupyterLab запустите из корня проекта командой `uv run --with jupyterlab jupyter lab`.

### 3. Данные

[PTB-XL 1.0.3](https://physionet.org/content/ptb-xl/1.0.3/): 21 799 ЭКГ длительностью 10 с от 18 869 пациентов, размеченных кодами SCP-ECG.

**Архив с данными:** <https://disk.yandex.ru/d/fplepF1sNN24LQ>

Скачайте `ptb-xl.zip` (около 1,8 ГБ) и положите его в каталог `ecg-warehouse/data/` (создайте каталог, если его нет). Распакует архив ноутбук первой части. Каталог `data/` исключён из git, поэтому данные не попадут в коммит.

### 4. Часть 1: датасет

Откройте `ecg-warehouse/notebooks/lab_dataset.ipynb`, запишите номер своего варианта в `VARIANT`, а его коды в `CLASSES` и выполните ноутбук, включая задания. Ноутбук загрузит PTB-XL в хранилище, соберёт датасет вашего варианта и экспортирует его в `ecg-ml/data/ptb-xl-variant-<N>`. Загрузка PTB-XL занимает заметное время. Если её прервать, повторный запуск пропустит уже загруженные записи.

### 5. Часть 2: классификатор

Откройте `ecg-ml/notebooks/lab_training.ipynb`, запишите в `VARIANT` тот же номер варианта и выполните ноутбук, включая задания: замените заготовку `ECGClassifier` своей архитектурой, обучите модель, оцените её на тестовой выборке и попробуйте улучшить.

### 6. Коммиты

Сохраните каждый ноутбук **вместе с результатами ячеек**, закоммитьте его в свою ветку и отправьте ветку в свой форк. Коммитьте только ноутбук: данные (`data/`) и логи обучения (`logs/`) исключены из git.

Из каталога для лабораторной:

```bash
cd ecg-warehouse
git add notebooks/lab_dataset.ipynb
git commit -m "Вариант <N>: датасет"
git push -u origin lab-variant-<N>
```

```bash
cd ecg-ml
git add notebooks/lab_training.ipynb
git commit -m "Вариант <N>: классификатор"
git push -u origin lab-variant-<N>
```

### 7. Запросы на слияние

В каждом из двух форков откройте запрос на слияние из ветки `lab-variant-<N>` в ветку `main` **вашего форка**. Не открывайте MR в исходные репозитории `unn-aicenter`: при создании MR проверьте, что целевой репозиторий — ваш форк. В названии MR укажите номер варианта, например «Вариант 3: датасет».
